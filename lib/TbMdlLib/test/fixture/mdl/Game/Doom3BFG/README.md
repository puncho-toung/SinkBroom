# Doom 3 BFG test game

A minimal Doom 3 BFG (RBDOOM-3-BFG) game directory for the TrenchBroom tests. `base/` is the
game's search path. Tests read the files through `getFixtureRoot() / "test/mdl/Game/Doom3BFG"`.

No id Software asset is included: no retail map, texture, model, material or sound. Every
file is either synthetic or taken from a CC0 or GPL source, as listed here.

| File | Origin | Licence |
|---|---|---|
| `base/materials/tb_test.mtr` | Written by hand for these tests. Neutral names; covers an editor image with a diffuse map, a diffuse map alone, `alphaTest`, `translucent`, `addnormals( a, heightmap( b, 4 ) )`, a `table` decl, a DDS-only image and the `nonsolid` surface parameter | GPL-3.0-or-later, like TrenchBroom |
| `base/textures/tb_test/wall_ed.tga` | 8x8 checker, generated by a script | GPL-3.0-or-later |
| `base/textures/tb_test/wall_d.png` | 8x8 checker, generated by a script | GPL-3.0-or-later |
| `base/textures/tb_test/grate_d.png` | 8x8 bars with transparent holes, generated by a script | GPL-3.0-or-later |
| `base/textures/tb_test/glass_d.png` | 8x8 half-transparent colour, generated by a script | GPL-3.0-or-later |
| `base/textures/tb_test/dds_d.dds` | 8x8 BC1 (DXT1) checker, one mip level, generated by a script | GPL-3.0-or-later |
| `base/_tb/fgd/DOOM-3-tbtest.fgd` | Classes `worldspawn`, `func_static`, `light`, `info_player_start`, `func_door`, `target_null`, `trigger_once` and `misc_model` cut unchanged from `base/_tb/fgd/DOOM-3-slim.fgd`, and `auto_generated_model` from `base/_tb/fgd/DOOM-3-models.fgd`, both written by the engine's `exportFGD` and `exportModelsToTrenchBroom` commands in the RBDOOM-3-BFG repository. `genmodel_tb_test_arrow` is written by hand in the exporter's format | GPL-3.0 (RBDOOM-3-BFG) |
| `base/_tb/models/tb_test/arrow.obj` | Written by a script in the format of the engine's `idRenderModelStatic::ExportOBJ`. An arrow along +X with a fin along +Z and a tab along +Y; two surfaces, 20 triangles. Normals are byte-quantised like the engine's (`GetNormalRaw()`), so 0 is written as 0.003922 | GPL-3.0-or-later |
| `base/_tb/models/tb_test/arrow.mtl` | Same, in the engine's `.mtl` format. Not referenced by `arrow.obj`, as in engine exports | GPL-3.0-or-later |
| `base/maps/tb_test_valve220.map` | Written by a script in the format of the engine's `idMapFile::Write` for Valve 220 maps (header, `// entity`, `// brush` and `// primitive` comments, `patchDef2` and `patchDef3`). A sealed six-brush room with a player start, lights, a brush `func_static`, a `func_door`, a `trigger_once` targeting a `target_null`, a `misc_model` with a proxy model, and a TrenchBroom group | GPL-3.0-or-later |
| `base/maps/test_box_valve220.map` | Copied unchanged from `maps/testmaps/test_box_valve220.map` of RBDOOM-3-BFG_mod_unittests (https://github.com/RobertBeckebans/RBDOOM-3-BFG_mod_unittests), with one comment line naming the source added after the two header lines. Its materials and model refer to retail assets that are not included here | CC0 1.0 |

`tb_test_valve220.map` follows the engine's writer but was not produced by the engine. Once an
engine build is available it can be regenerated with `convertMapToValve220`
(`plans/tb-rbdoom/06-build-test-verify.md` section 2.6, item 4).

Verified against the engine on 2026-10-10: `convertMapToValve220` reproduces `tb_test_valve220.map` apart from converter-only side effects, and rbdmap compiles it (7 world brushes, 2 patches, 10 entities, `.cm` CRC 2119697171). The engine has no DDS loader, so `textures/tb_test/dds` is editor-only.

Like the engine's exports, `.obj`, `.mtl` and `.fgd` files use CRLF line endings and `.map` files use LF; `.gitattributes` keeps git from normalising them.
